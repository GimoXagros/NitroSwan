Maintenance snapshot: 2026-09-03. See Docs/BaselineAudit-r7.md for audit blockers.
This is not a new release; History.txt remains the historical release record.

1. Current release status
   * r7 publishes the generic WSC-VideoCore-r8-test renderer (the internal test
     number is not a public r8 release).
   * DSpico-tested by the user: substantially improved character motion, but
     still open in current r7. No full OBJ-correctness claim.
   * User Oswan comparison: BGs correct; Rockman & Forte BG issue reported
     resolved during r7 testing. Preserve those scenes as regression controls.
   * CI/source-model checks/builds are not DSpico or native WonderSwan tests.
   * Maintenance audit: palette handoff interleaving fixed independently;
     renderer ABI and reset/ownership safety gaps still need closure before
     this can be called a fully safe next-feature baseline.

2. Highest-priority open defect
   P0 / Very high: remaining character-motion corruption in One Piece original
   and patched variants, Digimon Battle Spirit 1.0 / 1.5 / Frontier.
   "Fixed in r6 title-specific path" is historical validation; "improved in r7
   generic renderer" and "still open in current r7" describe the present.
   No new attempt to solve this defect is part of the baseline maintenance.

3. Next work order (difficulty estimates, not delivery promises)
   0. Safety prerequisite / High: close the audit's C/ARM stack alignment,
      state-load/reset and coherent publication gaps with executable tests.
      Keep all active upstream PR branches and r7 reference assets intact.
   1. P0 / Very high: capture OAM, decoded OBJ, sprite latch, palette and host
      VBlank generations together in the reproducible character-motion scenes.
      First prove or reject the suspected ownership cause; do not change the
      working BG path, sprite timing or copy count on a source-model guess.
   2. P1 / Medium: repeatable paired scene tests and separate WS-frame seed /
      host-VBlank publication copy metrics. objBytesCopiedFrame is SEED ONLY,
      not total bandwidth; count actual publications and define boundaries.
      Record palette drops, frame pacing, sound, input and saves.
   3. P1 / High: BG raster validation in Anode/Cathode battles, Final Lap
      2000/Special roads and Hataraku Chocobo transitions. Reproduce before
      fixing. Keep NitroSwan #59 / Sphinx #4 minimal and BG-only.
   4. P2 / Medium-high: 4-color 1024-tile maps (Sorobang, WSC BIOS).
   5. P2 / Very high: sprite-window edge clipping (Final Fantasy, Makaimura,
      Evangelion, Romancing Sa-Ga); Dicing Knight priority is a separate issue.
   6. P2 / Very high, hardware-dependent: native opcode-fetch timing vectors
      and proper V30MZ prefetch/refill for #60 / Sphinx #5 / ARMV30MZ #6.
      The shipped per-byte candidate is not an accepted prefetch model.
   7. P3 / High-very high: sound frequency/sweep/noise/LFSR/HyperVoice stereo.
   8. P3 / Very high: interruptible REP preserving flags, cycles and cache.
   9. P3 / Mixed: serial debug (low-medium), WSC high/low contrast and
      alternating Y (medium-high), mono 4-color mode (high), GUI cart jumper,
      and separately justified refactors. Do not mix these into OBJ work.
   Recommendation: safety prerequisite, then 1 with diagnostic parts of 2,
   then 3 and 4. No future feature branch is created by this audit.

4. Current validation gaps
   * tests/test_graphics_core.py is source-contract/Python model evidence.
     It does not simulate arbitrary IRQ scheduling or prove pixel correctness.
   * Some audit tests deliberately demonstrate OLD/OPEN counterexamples:
     their success means the counterexample is reproduced, not safety passed.
   * Fresh emulator and DSpico scene/performance checks for maintenance changes
     are pending; historical r6/r7 runs must not be relabelled as fresh passes.
   * Native WonderSwan prefetch/scanline vectors pending; DSpico is not native WS.
   * Mode transitions: mono/color, 2bpp/4bpp, packed/planar, LCD, BIOS,
     reset/eject/replacement and save-state restore need interrupt-aware checks.
   * Palette event overflow, generation wrap and WS/host frame metric boundaries
     need explicit stress coverage; no new timing/renderer flag in this task.
   * Clean builds verify assembly/link/package, not game compatibility.

   OPEN:
   * One Piece original/patched and Battle Spirit 1.0/1.5/Frontier: P0 above.
   * Dicing Knight: shadows in front of player (OBJ/FG priority).
   * Anode/Cathode: historical missing battle gradients, generic r7 recheck pending.
   * Final Lap 2000/Special: historical road palette issue, generic recheck pending.
   * Hataraku Chocobo: map-transition BG raster validation pending.
   * Final Fantasy: dialog sprite windows.
   * Makaimura: intro right edge / first-boss sprites (window, further cause open).
   * Evangelion and Romancing Sa-Ga: overlapping sprites/window priority.
   * Sorobang and WSC BIOS: need 1024 tiles in 4-color mode.
   * Cardcaptor Sakura and Mr. Driller: timing-sensitive.
   * Dekadence - Vesilintu, Mingle Magnet, Nazo Ou Pocket, Puyo Puyo Tsuu,
     Side Pocket, Time Bokan: historical slowness reports; no fresh r7 benchmark.
   CONTROLS / LIMITED POSITIVE RESULTS:
   * Rockman & Forte BG: user-reported resolved during r7; not whole-game certified.
   * One Piece sky: original and patched title-specific r6 path emulator-tested
     and DSpico-tested; current r7 generic BG comparison reported correct.
     This is distinct from the OPEN character-motion issue.
   * Mahjong Touryuumon: custom.r5+ speed/sound/input DSpico-tested; native
     instruction prefetch timing still pending.
   * Armored Unit menu BG shake: historical report matches native HW.
   * Chou Denki Card Game: requires NVRAM initialization, first page last item.
   * Beatmania: memory-capacity limitation, not a new regression here.
