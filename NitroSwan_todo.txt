NitroSwan Todo (post v0.7.7-custom.r7 review, 2026-09-02)

	Release status:
	* r7 publishes the internal WSC-VideoCore-r8-test renderer.
	* User DSpico testing: character-motion corruption is greatly reduced but
	  still present. Release approved with this known limitation; NOT fully fixed.
	* User comparison against Oswan: backgrounds are correct. Rockman & Forte's
	  background issue is reported resolved; keep it in the regression set.
	* The earlier "fixed" notes below describe historical test results, not an
	  exhaustive guarantee for the current generic renderer.

	Completed through custom.r6:
	* Fixed 16KB RAM behaviour on mono consoles.
	* Fixed RTC invalid values, calendar month lengths, leap years and rollover.
	* Replaced the global DSpico MPU mapping with a NitroSwan-only 64KB ROM bank
	  cache, preserving NDS_Shared and BlocksDS memory aliases.
	* Restored opt-in game-specific idle-loop speed hacks with cache coherency.
	* Fixed ROM-load Data aborts for ASCII, Korean and Japanese filenames.
	* Restored the V0.7.7-custom video/audio/CPU hot paths after r2 regressions.
	* Auto-created /nitroswan and default settings.cfg; hidden folders remain usable.
	* Fixed Pico Loader first-ROM reads and direct-launch NVRAM save paths.
	* Enabled and exposed automatic NVRAM saving, including save-on-exit.
	* Fixed One Piece Grand Battle Swan Colosseum OBJ tile tearing on hardware for
	  the Japanese original ROM with a title-bounded 4bpp OBJ double buffer and
	  sprite latch. custom.r6 selects the path using stable product identity so
	  modified ROMs are not excluded solely by their checksum.
	* Added the missing background-color-register replay to DS BG_PALETTE[0]. The
	  original ROM battle sky and character graphics are correct in melonDS and on
	  DSpico hardware. r6 also verifies the Korean-patched ROM.
	  This does not complete the general per-line palette task for other games.
	* Added cached cartridge opcode/immediate-fetch waitstates for $A0 bit 3.
	  Mahjong Touryuumon speed, sound and input are confirmed normal on DSpico.

	Completed in custom.r6:
	* Removed the One Piece exact-checksum identity dependency. Publisher, color,
	  product ID and the low 7 revision bits now select both compatibility paths.
	* Replaced per-line palette scanning with bounded write-time events for the
	  background-color register and WSC palette RAM only.
	* Japanese original and Korean-patched DSpico validation passed for sky,
	  character tiles, rapid movement, status/UI, sound, input and frame pacing.

	Implemented in custom.r7 (partial improvement, not full OBJ correctness):
	* Generalized the sparse BG palette/backdrop event path to color hardware and
	  removed game identity from renderer correctness.
	* Generalized the line-142 sprite-table latch. Two decoded 16KB OBJ snapshots
	  now live in main RAM: dirty generations conditionally seed the off-screen
	  snapshot, and only the last completed generation is copied to fixed OBJ VRAM
	  at host VBlank. A partial next 75 Hz frame therefore cannot overwrite the
	  60 Hz displayed sprites. OBJ conversion remains restricted to 512 tiles.
	* Limited sparse BG replay to WSC palette entries 0-127. Entries 128-255 feed
	  OBJ palette conversion and must not overwrite DS BG palette slots.
	* Added a conditional off-screen 32KB BG character bank. Decoded tiles are
	  prepared outside the displayed bank and BG0/BG1 switch generations at VBlank,
	  avoiding live tile replacement during rapid selection/battle transitions.
	* BG character-bank publication now occurs only for completed WS frames, so a
	  partially executed next 75 Hz frame cannot publish its decoded character
	  generation at host VBlank. The experimental rotating tile-map destinations
	  were removed after their shared dirty-row cache caused incomplete maps; the
	  established single-destination map conversion and line-144 OAM timing remain.
	* r8-test passed 48 host Python source/model tests and DS/DSi builds.
	  User hardware testing confirms residual character corruption; complete
	  resolution is deferred. See Docs/ReleaseValidation-r7.md for test limits.

	Next work plan after custom.r7 (recommended order; difficulty is an estimate):
	1. [P0 / Very high] Finish residual One Piece / Digimon character-motion
	   corruption. Trace OAM/tile/latch/palette/host-VBlank generations together;
	   test atomic publication, partial next frames and animation latency. Do not
	   assume the remaining cause is proven. Preserve working BG and r7 baseline.
	2. [P1 / Medium] Add repeatable scene regressions and full transfer metrics.
	   Include OBJ VBlank-copy cost (not currently counted by objBytesCopiedFrame),
	   dropped palette events, audio and frame pacing. Recheck original/patched
	   One Piece, three Battle Spirit games, Rockman & Forte, and WS/2bpp controls.
	3. [P1 / High] Validate generic BG raster in Anode/Cathode battles, Final Lap
	   2000/Special roads and Hataraku Chocobo map transitions; address only
	   reproduced defects. Keep upstream BG-only PR #59 separate from OBJ work.
	4. [P2 / Medium-high] Add 4-color 1024-tile maps for Sorobang and WSC BIOS.
	   Verify bank selection and dirty-cache coverage without regressing 4bpp.
	5. [P2 / Very high] Implement efficient sprite-window edge clipping for
	   Final Fantasy, Makaimura, Evangelion and Romancing Sa-Ga. Investigate Dicing
	   Knight sprite priority separately; DS layer limits may require trade-offs.
	6. [P2 / Very high, hardware dependent] Run opcode-fetch hardware vectors and
	   research actual V30MZ prefetch/refill behavior for PR #60. Preserve the
	   Mahjong game-level improvement; do not add arbitrary per-byte penalties.
	7. [P3 / High-very high] Revisit sound frequency writes, sweep/noise timing,
	   LFSR and HyperVoice stereo as separate changes with DSpico audio tests.
	8. [P3 / Very high] Make REP strings interruptible while preserving CPU flags,
	   cycles, cache coherence and the proven 3DS performance path.
	9. [P3 / Mixed] Serial debug mapping (low-medium), WSC contrast (medium-high),
	   mono 4-color mode (high), and remaining GUI/refactor items. Work separately.

	Recommendation: do 1 and its diagnostic part of 2 together; then 3 and 4.
	Do not mix CPU timing, audio, sprite windows or broad rewrites into the
	remaining character-corruption investigation.
